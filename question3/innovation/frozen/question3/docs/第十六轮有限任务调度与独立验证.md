# 第十六轮：取消固定强制扫描，保留有限任务与可靠停止

本轮采纳 FREE 作为**自建环境研发推荐**：在第十三轮 BOTH 上仅设置 `search_interleaving: nearest_finite`，取消连续两次定位后的强制扫描，扫描和所有已知定位任务仍按原入口距离统一比较。没有缓存优先或已知目标优先，也没有调整数值参数。AB、S、1125米固定环、数量证书、延后原地第二检测和公开半平面/圆跳过保留。第四问未开展，最终比赛方案未冻结。

这是一项删除人为调度约束的改进，不包装为新的优化算法。相对第十三轮的收益只能由配对实验支持；不能据此推断全局最优、对每局更快，或与历史其它模块必有协同。

## 理论复核与不变条件

在题面全向、固定源、频道互异且源数最多16、接收与角度误差满足约束的模型内：

1. 扫描只选择未访问站点；正常完成后加入已访问集合。数量先验触发时可在扫描中途返回，此时不伪造该站完整阴性记录，而是因已发现16个不同频道而不再安排未知源扫描。因此扫描任务不重复，至多7次。
2. 每次成功定位任务清除一个尚未清除的不同频道，至多16次。共享检测只针对已知频道。近源清除也消耗源，不制造新任务。若覆盖点全部失败或发生时限/传输/模型错误，程序报告 incomplete，不会重新无限安排定位。
3. 故成功运行的调度任务总数至多23；连续两次后强制扫描不是有限性所必需。有限任务数**不等于**保证在所有场景、所有服务器故障下满足时间预算。
4. 完成仍要求逐频道七站覆盖证书，或16个不同频道成功清除的上限证书。只发现16个只停止未知源搜索，必须清除已知源。不会以找到10个、连续无信号或清空当前队列作为完成依据。

第二问的接收/交角候选保证、1.005度误差上界、28米光学覆盖和执行前分离证据没有更改。它们保证合法候选和覆盖；离散 A 代价代理及最近入口均是启发式，不是通用最优性证明。固定同点误差未通过重复检测取平均。策略仅使用接口可见反馈，隐藏真值只在运行后的独立审计中读取。

## 预注册、范围与真实执行

协议 `docs/round16_protocol.json` 在开发前记录，仅 REF/FREE 两配置、没有数值搜索。开发主/舍入均通过“全部完成且审计通过、均值严格下降、P95不升”后，锁定 `results/round16_lock.json`；之后生成普通210000～210049和外缘220000～220019，各四个固定误差场。新场景每个误差处理批次均使用同样门槛，未看验证结果后改门槛或切换候选。

开发208局；复用旧困难例60局（15配置×两策略×两误差处理）；新验证1120局（70个新布局×四误差场×两策略×两处理），共1388局、167974个接受动作审计。布局是统计重复的基本单位，四误差场和两种舍入处理不算独立布局。全部完整清除；失败、超时、假完成均为0。134条 REF 指标及状态与上一轮逐项一致。统计保留全部案例，若失败则原分析器保留失败并施加至少360000秒惩罚，不删除失败算漂亮均值。

外缘两条首次启动命令误写 fixture 文件名，在读取案例前报 FileNotFoundError，未执行策略；原空目录和报错日志保留为 `round16_outer_*_startup_failed`。修正为已生成的 `round16_outer_holdout_cases.json` 后重新运行，没有重生成数据或更改源码锁。此为启动错误，不混入合法场景成功局数。

142项测试实际通过（`results/round16_tests.txt`），包括晚出现频道20、最小接收半径边界、选项未被过滤、延长定位期间主动触发时限仍返回 incomplete；原HTTP错误/幂等/证书失败路径也运行。真实 CLI→本机临时端口自建HTTP另跑1局，完整清除，3834.871127秒，21个调度任务、无强制扫描。此网络测试没有连接官方exe。

## 最差案例与对抗复核

- 新普通最差相对回归 `holdout_210032_positive`：3747.96→4209.26秒，+461.30秒/+12.31%。首次调度分歧在第4个任务：REF强制扫描4站，FREE先定位11频道。少6次检测、少6秒切频，却多485.30秒移动及4次失败清除（+12秒）。更近入口不等于后续路径更短。
- 新普通 FREE 最慢 `holdout_210044_smooth`：5294.85→5679.99秒，+385.14秒；其中搜索阶段+398.01秒、定位+68.97秒、光学阶段−87.84秒，另共享阶段+6秒。首次分歧为REF扫描5站、FREE定位15频道。这指出扫描站顺序和任务完成位置的耦合仍未解决。
- 旧外缘 `outer_holdout_120008_spatial_hash`：5150.42→4259.81秒改善；但旧普通 `holdout_130023_smooth`：5514.16→5781.25秒变慢，`holdout_130023_negative`：5618.75→5894.04秒变慢。不能把旧最差案例整体宣称已解决。

- 核查了可靠停止和有限性命题的前提：接受反馈为准、部分扫描不作完整阴性、超时不报完成、策略不读隐藏值。几何保证不推出运行成本保证；浮点分离仍采用既有保守余量，未声称形式化区间运算证明。

## 下一项最值得验证的机制（尚未实现/验证）

**剩余扫描站的完整路径代价**：已知扫描站最多7个，可用小规模子集动态规划求“当前点经过剩余扫描站的最短开路”，以其首站代替单纯最近扫描站，定位任务的原入口竞争先保持不变。这个实验只修改扫描路径排序，与之前“一步定位终点前瞻”、强制定位批次不同；先做一个固定配置，不引入权重调参。

动机是新最慢例搜索阶段额外398秒，当前最近站路径会在定位后改变且可能留下长距离扫尾。预计有机会减少末段跨区移动，代价是更远的首站可能推迟新发现、共享检测或改变清除位置。若剩余站以后因16源证书而免扫，完整路径代理还可能高估工作量。它不是全局路径最优策略。

后续对照应为已采纳 FREE 与该单项，先复用固定开发/困难场、相同误差和预算，再另锁新的布局；若两误差开发均值/P95任一不满足门槛，或完整清除/证书出现失败，放弃。当前验证布局已看过，不能再称后续的独立新验证。此处仅提出机制，不填造收益。
