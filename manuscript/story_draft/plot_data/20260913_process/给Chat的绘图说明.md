## 图一：累计虚拟时间—已清除源数

### 给 Chat 的指令

请依据 `formal_clear_times_wide.csv` 绘制一张含 Q3、Q4 两个子图的论文用过程折线图。

- 横轴 `k_cleared`：成功清除的干扰源数 $k$，使用整数刻度。
- 纵轴：该次成功 `/clear` 响应中的累计虚拟时间 $T_k$，单位 s。
- Q3 使用 `Q3_formal_1_T_s`、`Q3_formal_2_T_s`、`Q3_formal_3_T_s` 三列；Q4 使用对应的三个 Q4 列。每条细线表示一次正式测试，图例“正式1”“正式2”“正式3”。两个子图分别设置纵轴范围，不共享纵轴尺度。
- 在每个实际成功清除点标记圆点；`k=0,T=0` 是成功入场原点，可用空心点区分。
- 按原数据直线连接，不平滑，不画均值、置信带或拟合曲线。空值表示该运行没有对应的第 $k$ 个清除点，必须在最后一个非空值停止，不补零、不外推。
- 可根据 `formal_run_summary.csv`，从最后清除点向相同横坐标的退出总时间绘制灰色竖向虚线并加空心方框，标注“后续扫描核验至退出”。只有退出时间大于最后清除时间时才画；退出点不是新增清除点。
- 若需要标记 Q4 光学回退，可从 `formal_clear_trajectories.csv` 关联 `phase=optical_fallback` 的成功点，用三角形替换圆点。不将“发生回退”解释为清除失败。

推荐图注：

> 第三、四问各三次正式测试的累计虚拟时间运行轨迹。每条线对应一个正式案例，点为成功清除响应，原点为成功入场；Q3三次分别清除10、16、12个源，Q4分别清除10、15、11个源。时间包含此前全部移动、切频、检测、光学尝试与清除费用，不含程序墙钟时间。灰色虚线（若绘制）表示最后清除后继续扫描核验至退出的耗时。每问仅三个案例，本图不作总体均值或置信区间推断。

### Q4事件数据（可选，不建议全部叠加）

`formal_q4_events.csv` 保留全部可定位事件：

|`event`|含义|时间位置|
|---|---|---|
|`no_signal`|测向无信号|测向响应完成时刻|
|`optical_fallback_start`|开始一次光学网格服务|首个回退动作之前的上一响应时刻，尚未计入该动作移动及光学费用|
|`optical_fallback_success`|回退过程中成功清除|成功清除响应完成时刻|
|`clear_no_target_in_range`|光学范围内没有目标|失败清除响应完成时刻|

`k_cleared_before`、`k_cleared_after` 是事件前后实际清除数。若画事件散点，使用这个整数计数和实际虚拟时间，不能把事件插值到相邻清除点之间的任意横坐标。

Q4无信号分别为282、205、277次，其中已发现频道上的无信号为12、44、23次；`channel_previously_discovered=1` 可筛出后者。许多未知频道可能本就没有源，不能将所有无信号都解释成定向源背面失联。光学回退分别有4、6、7次，失败光学尝试分别0、5、6次；两种计数含义不同。

## 图二：Q3区域收敛（已有正式状态记录）

检查发现，正式策略日志已保存每次 `feasible_update` 后的多边形顶点。现已补算覆盖半径，并以动作响应、哈希一致的几何源码重建全部区域核验。无需重跑正式测试。

### 给 Chat 的指令：正式轨迹版

请用 `q3_convergence_official.csv` 绘制 Q3 定位区域覆盖半径过程图，并读取 `q3_convergence_official_source_summary.csv` 标记终点类型。

- 按 `formal_index` 分为三个子图；每个 `source_curve_id` 是一条源轨迹，不能把不同频道首尾相接。
- 横轴 `bearing_count`：该源正常有效测向次数；只计 `direction`，不计 `no_signal` 或 `near`。横轴采用整数刻度。
- 纵轴 `covering_radius_m`：最新示向方向旋转包围盒中心 $q$ 对当时多边形 $P$ 的覆盖半径 $R(P,q)=\max_{v\in V(P)}\|v-q\|$，单位 m。可用对数纵轴显示约750 m至数米的变化，轴名中注明“对数尺度”。
- 添加 $R=20$ m 水平虚线。原始点连线、不平滑，不把不同源平均，不画置信带，不强制单调。
- 按 `source_curve_id` 关联 `clear_method`。`near_feedback` 源的最后一个正常测向点可用空心方框，并说明“随后由近场反馈清除”；不得添造 $R=5$、$R=0$ 或低于20 m的新测向点。只有一个点的轨迹保留单点。
- 本图三次分别有25、45、32个状态，分别对应10、16、12个源，共102状态、38条源轨迹。独立单位是三个正式案例，38个源不是38个独立布局。

推荐图注：

> Q3三次正式测试中，各源随正常有效测向次数增加的位置区域覆盖半径。指标由当时策略日志的多边形顶点计算，中心取最新示向方向的旋转包围盒中心；虚线为20 m清除阈值。三次分别包含10、16、12个源及25、45、32个区域状态。7个源随后由近场反馈直接清除，其轨迹保留最后一次正常测向的半径，不补造新的区域状态。本图为运行轨迹，不是平均收敛速率。

`algorithm_radius_with_slack_m` 另存算法使用的数值半径（几何半径加 $10^{-7}$ m），主图使用 `covering_radius_m` 即可。虽然本批没有半径上升步，旋转中心变化意味着区域嵌套本身并不能保证该半径严格单调。

## 图三：Q4发现过程（历史冻结运行重建）

正确配对来源为 `question4/results/round9_main` 和 `round9_rounding`。每批96个独立布局，每布局一个预定误差条件，两种方案配对；每批四种误差模式各分配24个布局，**不是同一布局重放四次**。两批共192个独立布局、384次配对方案运行。

原始逐动作日志不在当前工作区，因此本图由各批SHA256核验过的冻结历史源码、配置及布局离线重建。384次均与历史汇总的状态、清除数、虚拟总时间和动作计数一致，分项与阶段浮点总量在容差内一致，且通过原版动作审计。它们是历史运行重建，不是新增独立验证或正式测试。

### 给 Chat 的指令

请从 `q4_discovery_summary.csv` 筛选 `source_stratum=all_10_to_16`，按 `batch` 绘制两个子图：`round9_main` 标为“读数包络”，`round9_rounding` 标为“舍入压力”。

- 横轴 `station_index`：已完成整站必要频道扫描的测站数；0为尚未扫描。
- 纵轴 `count_median`：累计发现的不同频道数中位数；阴影用 `count_q1` 至 `count_q3`，注明“四分位范围（IQR）”，不能称为置信区间。
- `arm=baseline31` 为31站初始方案，绘制0—31；`arm=recommended25` 为25站推荐方案，只绘制0—25。不要把推荐方案画成实际扫描了26—31站。
- 两种方案各使用同一批96个配对布局，不平滑，不挑选特定有利案例。累计发现数包含已经清除的频道，清除不会使发现数下降。
- 部分16源布局提前停止扫描。为保持每个横坐标的样本构成一致，汇总在提前停止后保持最终发现数16。`n_carried_forward` 标出持平延伸的布局数，`n_observed_scan_endpoints` 标出该坐标有实际扫描记录的布局数，两者之和为 `n_independent_layouts`。延伸点不是新增扫描行为，图注必须说明。
- 全体布局包含10—16源，曲线平台受源数差异影响。若重点展示发现第16源后的提前停止，可另把筛选条件改成 `source_stratum=n_sources_16`，每批使用全部12个16源布局；添加 $y=16$ 虚线，图注明确12个独立配对布局。不要把这个子集标成96布局。

推荐图注：

> Q4的31站初始方案与25站推荐方案的累计频道发现过程。两批各96个独立配对布局，每布局一个预定误差条件，包含10—16个源；实线为中位数，阴影为布局间四分位范围。发现数在整站必要频道扫描完成后记录，包含已清除频道。提前结束的运行保持最终发现数以维持样本构成，此类延伸不表示继续扫描；25站方案只绘至第25站。过程数据由冻结历史源码离线重建，384次运行均与原汇总核对一致。本图不表示各布局均改善。

补充结果便于核对：首次发现全部源时的已扫描站数，中位数在读数包络批次为31站方案20、25站方案15；舍入批次为20.5和18。25站方案所需扫描数更少/相同/更多的配对布局分别为72/2/22和62/5/29。该指标是发现进度，不能直接当成总耗时，也不能代替连续覆盖证明。对于不足16源的布局，首次发现全部源时算法尚不知道已经全发现，通常仍需继续完成覆盖核验。

## 来源和复现

- 图一：`formal_data_provenance.json` 保存六次运行、公开正式日志头、来源文件SHA256及提取规则。原行为正文未解密。

在仓库根目录可依次运行以下脚本重建导出数据：

```bash
python manuscript/story_draft/analysis/export_formal_process.py
python manuscript/story_draft/analysis/export_q3_convergence.py
python manuscript/story_draft/analysis/export_q4_discovery.py
```

前两个脚本需要本地保留的正式动作/策略日志；Q4脚本仅调用自建SELF模拟器与冻结历史源码，不访问正式测试接口。绘图数据包不包含原始逐动作日志、加密行为正文或模拟器凭据。
