# 第三问第七轮：利用题面数量上限，保留较简单的K方案

本轮研发推荐为 **K：第五轮COMPACT_BATCH + `count_stop=detected_16`**。AB、批量共享S、1125米固定环继续保留，D、I、V保持关闭。改进来自题面明确给出的源总数上限，未调整数值权重，也没有增加关于源位置或误差的先验。

第二次锁定后，K在新的普通布局主批均值节约16.84秒（0.376%），外缘主批节约3.09秒（0.073%）；两组P95未增加，本批无单例变慢。多数案例完全不变，收益不能夸大为普遍的大幅提速。此前候选DK虽然均值更低，但没有通过其事先约定的P95门槛，未采用；K经过另一次锁定和另一批新案例验证后才推荐。

目标仍是持续降低第三问整局时间，尚未宣称达到最优或完成最终方案冻结。仅Ubuntu自建测试，官方exe、官方演练、正式测试均未启动。

## 1. 上限是题面条件，不是推测

题面第三问明确总数在10—16个之间，附录1说明频道互不相同；附件2再次规定每频道最多一个源、总数10到16个。证据见`题面_提取.txt`第27、65行及`附件2_提取.txt`第25—27行。具体总数不通过接口返回，策略始终未读取隐藏总数。

设已通过有效方向/近场观测或成功清除确认存在的不同频道集合为F，收到有效成功清除反馈的不同频道集合为C。题面条件给出 `|C| ≤ |F| ≤ N ≤ 16`。

- 若`|F|=16`，由上下界夹逼得到`N=16`，其余频道不再需要搜索；但F中未成功清除的源必须继续定位、清除。
- 若`|C|=16`，则所有源已清除，可以完成退出。
- 如果最终不足16个成功清除频道，仍须逐频道满足“已清除或七个覆盖站有效无信号”的原证书。10个、15个或多次无信号都不是独立退出条件。

程序使用集合而非尝试次数；重试同一成功响应不会增加不同频道数。未完成扫描的站点不被标记为完成，也不填造无信号记录。计数证书明确记录`method=source_count_upper_bound`、上限16、16个成功频道及由数量上限推断的其余4个无源频道；原证明记为`seven_station_channel_cover`。独立审计从实际接受的成功响应重建清除集合，拒绝15次成功却伪造16源证书的结果。

这是在题面条件下可证明的可靠停止，不是“观察到一些源就猜测全部找完”。如果设备或未来另一题不再满足总数≤16，该证书不能沿用。本轮没有发现题面与附件在这个上限上存在歧义。

## 2. 三个开关与原成果

**D**：已有单圆清除。完整凸候选区所有顶点均在一个半径小于20米、带数值余量的圆内时，改成在圆心尝试一次清除。逐顶点验证保证整个凸区域被覆盖。它改变清除位置，未证明后续路径更快。

**U**：`count_stop=cleared_16`。只增加16个不同频道成功清除后的立即退出；此前的搜索定位流程不变。在同一合法案例、相同响应场下，它的虚拟动作是原流程的前缀，因此完成局的虚拟时间不增加。这个结论不声称现实计算时间或网络可靠性支配原版。

**K**：`count_stop=detected_16`。更早在发现16个不同频道时结束对未知频道的搜索，随后清除所有已知源，满16次不同频道成功后退出。省去的是已经可以证明无必要的搜索。K可能改变后续定位顺序和第二点，因此**没有证明K整局时间对任意布局均不增加**；安全性证明与时间优势分开。

对照包含REF、D、U、DU、K、DK。REF为第五轮COMPACT_BATCH；不是第四轮同名REF。D还与上一轮V比较，D+V仍出现舍入压力P95退化，保留结果、关闭V。Q1/Q2定位几何和时间代理、HTTP接口、自建物理/误差环境未修改。本轮实质改动是公共流程的计数状态、停止证书和独立审计分支，默认`count_stop=off`保留旧行为。

## 3. 顺序、数据隔离与总量

1. 先写`round7_protocol.json`，复核D/V/DV与REF：既有52开发配置×4方案×2误差模型=416局。
2. 核对题面上限后写`round7_count_protocol.json`，测试六方案：52×6×2=624局。另复用四个已知反例，共48局开发诊断，不能称为新验证。开发共1088局。
3. 根据开发结果选DK，写`round7_lock.json`后生成普通种子70000—70049、外缘80000—80019。50普通+20外缘布局，各4固定误差场、两种舍入模型、六方案，共3360局。DK因一项P95增加0.306秒，按原门槛拒绝；没有临时扩大容忍值。
4. 根据这批对照选择较简单K后，前一批对K而言成为选择依据，不再作为K选择后的独立验证。写`round7_k_lock.json`，无代码或参数修改，再生成普通90000—90049、外缘100000—100019。另一组50+20布局，4误差场、两种模型、REF/K两方案，共1120局最终独立验证。

两次采纳规则都在各自锁定时写明：完整清除与审计全部通过，每个新普通/外缘及舍入批次均值严格低于REF、P95不高于REF。第二阶段K四批均通过。没有用最终新案例继续调参或选择别的候选。

本轮合计 **5568局自建实验全部完整清除，失败/超时/假完成均0；独立审计664270条动作**。全部失败尝试与费用保留，未删除任何失败局后取均值。第一阶段70种新布局与第二阶段另70种新布局不同；不能把配置/误差组合当作几千种独立布局。87项第三问测试通过，其中8项新增测试覆盖计数证书、15源不能伪造16源、迟发现源、发现未清除、截止时间和末次清除响应丢失重试等关键路径。

源布局和空间误差函数在同一批各方案之间完全相同。同点同频道误差固定，四种场为spatial_hash、smooth、positive、negative；策略不知道场的类型。两种误差模型为严格±1度后取两位小数的主模型、允许到±1.005度的舍入压力模型。后者在策略统一误差包络内。所有比较使用实际整局虚拟时间，包含移动、切频、检测、光学和激光，不只比较局部定位精度。

开发审计增加了证书字段一致性检查后，对624局数量上限开发日志重新检查通过。104局关闭新功能的REF与第五轮费用分解、清除状态和审计结果完全一致。第一阶段与开发的U/DU动作前缀核对1344对通过；K/DK在少于16源时的1152对费用分解完全相同。第二阶段另488对少于16源的K/REF完全相同。

## 6. 耗时分解与仍未解决的问题

普通主批，REF→K平均费用：移动3823.92→3810.69，切频92.87→92.25，检测470.00→466.98，光学69.27→69.30，激光26.52→26.52秒。搜索阶段减少25.95秒，但独立定位阶段多9.11秒，最终净省16.84秒。即便删除了不必要搜索，后续路径也会改变，不能将全部搜索节约直接等同于整局收益。

外缘主批平均移动少2.18秒、切频少0.16秒、检测少0.75秒，光学和激光不变。压力外缘几乎只少0.625秒的检测/切频，移动没有减少。

已知开发聚集案例`clustered_16`从第五轮2483.57降至K的903.16秒，约63.63%改善；普通开发seed0从4919.73降至4429.44秒。这两个案例另经真实Ubuntu本机HTTP命令运行，均有16个不同成功频道的数量证书；它们不是最终独立验证。

第二阶段绝对最慢普通案例`holdout_90015_smooth`为5797.61秒；外缘`outer_holdout_100006_negative`主批6484.31、压力6490.16秒。两例都是16源，但K与原版相同，说明上限条件确认太晚时不能解决搜索路线和定位往返问题。第五轮曾有24.44%的批量共享退化，本轮不声称已经修复；相对本轮REF没有新退化，也不等于相对更早版本始终更快。

下一项值得验证的是把**当前机器人位置**作为第二检测点的机会候选：只有通过第二问完整解析候选条件时才加入，与原离散候选使用同一费用目标竞争。动机是继续减少定位往返，而不是增加采样权重或假设真实方位误差独立。本轮未实现、未验证该机制；尤其需要检查更差交会几何和后续路线是否抵消零移动的收益。
