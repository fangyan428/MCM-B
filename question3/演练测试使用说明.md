# 问题3最终方案演练测试使用说明

本文用于在 Windows 官方模拟器上测试当前冻结的第三问推荐方案，并说明如何先做本机回归、如何保存日志、如何计算演练统计量。

> **Git pull 后新增方案的专用入口**：当前新增候选为 `GATED_TOUR_MULTI_PARALLAX`，必须使用 `python -m question3.run_innovation_http`。它不使用 `--config` 参数，程序会固定读取 `question3/innovation/best_candidate.json`。旧的 `python -m question3.run_http --config question3/configs/recommended_omni.json` 仍然是原 `round19_BOTH` 方案，两者不要混用。

## 0. 新方案快速演练命令

如果你只需要立即测试 Git pull 后的新方案，按下面顺序执行。

先在项目根目录确认代码版本：

```powershell

python -m pip install -r question3/requirements.txt
```

先做本机回归（两个 PowerShell 窗口）：

窗口 A：


窗口 B：

```powershell
python -m question3.run_innovation_http `
  --mode self-http `
```

## 3. Windows 官方演练的完整操作流程

### 3.1 启动模拟器并选择正确模式

1. 双击项目根目录中的 `jammers-simulator.exe`，或从资源管理器启动它。
2. 确认电脑联网，完成模拟器在线登录和服务器时间校验。
3. 在模拟器中选择“问题3/全向干扰源”的**演练测试**。界面文字可能略有差异，但必须是 rehearsal/practice，不得选择 formal/正式测试。
4. 确认开始后等待案例准备完成、5 秒倒计时结束，并等待界面显示“机器狗接口已经就绪”。接口未就绪时运行脚本会连接失败，这是正常的保护行为。

官方接口默认只监听本机：

```text
http://127.0.0.1:2026
```

如果在模拟器空闲时手工改过端口，必须把实际地址通过 `--url` 传给脚本；不要让自建服务占用 2026 端口。

### 3.2 运行新候选客户端

接口就绪后，立即在项目根目录的第二个 PowerShell 窗口执行：

```powershell
python -m question3.run_innovation_http `
  --mode official-rehearsal `
  --confirm-rehearsal-ui `
  --robot-id YOUR_TEAM_ID `
  --output question3/results/windows_innovation_001
```

替换规则：

- `YOUR_TEAM_ID` 必须替换为当前模拟器登录的真实参赛队号，逐字节一致；不能使用默认值 `SELF`。
- `windows_innovation_001` 必须是新的、尚不存在的目录。下一次使用 `002`、`003` 等新目录。
- 如果端口不是 2026，增加例如 `--url http://127.0.0.1:2030`。
- `--confirm-rehearsal-ui` 只是操作者确认“当前界面是演练测试”，不是程序对模式的技术识别。HTTP 接口无法判断你是否误选了正式测试。

代码不会启动 exe、不会点击模拟器按钮、不会读取隐藏案例，也不会自动选择演练/正式模式；选择测试模式必须由操作者在模拟器界面完成。

### 3.3 脚本实际执行的动作

新候选的执行链路为：

```text
接口就绪
  → /enter
  → 原点及七站搜索、逐频道 /measure
  → 维护每个已知频道的保守可行区域
  → 视差检测和滚动路线调度，必要时在当前位置共享检测其它频道
  → 可行区域被20米圆证书覆盖时 /clear；否则继续自适应测量
  → 以16个成功频道、七站全覆盖或（若启用）连续覆盖证书判定完成
  → /exit
```

策略不读取源位置、源半径、源总数等隐藏真值。`no_signal` 只表示该位置当前频道未收到信号，不能单独解释为“附近没有源”；只有 `measure_result=direction` 时才读取 `svd_deg`，`near` 不含方位角。`/clear` 不切换测向机频道，只有 `/measure` 会产生切频耗时。

## 4. 必须遵守的接口和时间规则

这些规则由 `question3/interface.py` 和附件2共同约束：

- 先成功调用 `/enter`，再调用 `/measure`、`/clear`，最后主动调用 `/exit`。
- 每个新动作使用新的 `request_id`；只有网络超时或连接中断时重试完全相同的动作，才复用原 ID 和原请求体。
- 请求必须串行发送，收到本次完整 HTTP 响应后才能发送下一步；不要并发发送不同动作。
- 同时检查 HTTP 状态和 JSON 中的 `accepted=true`。`accepted=false` 不推进动作，响应中的 `virtual_time_s=0` 不是当前虚拟时刻。
- `robot_id` 必须与模拟器当前登录队号完全一致；请求体不能增加未声明字段。
- `/enter` 返回的 `remaining_real_duration_s` 是本局实际剩余现实时间，程序不能固定假定一定有 1200 秒。
- 25 分钟窗口和 `/enter` 后最多 20 分钟取较早截止时刻；越晚进入，实际可用时间越短。5 秒检测耗时是虚拟时间，不需要在现实中等待 5 秒。
- 测试因超时、手工中止、接口关闭或技术异常结束后，不要再调用 `/exit` 查询原因，也不要在不确定上一步是否执行时盲目换新 ID 重发。
- 坐标必须为有限数，且每个分量绝对值不超过 2,000,000；频道必须是 1～20 的整数。

## 5. 运行结束后的验收和记录

### 5.1 客户端输出目录

每次演练的输出目录应保留以下文件，不要覆盖或删改：

| 文件 | 用途 |
|---|---|
| `config.json` | 本次实际使用的配置副本；核对 `mechanism=gated_tour_multi_parallax` 和内层 `baseline_config.name=round19_BOTH` |
| `code_sha256.json` | 新入口写入的入口、公共客户端和创新目录源码摘要 |
| `actions.jsonl` | 每次请求、响应、HTTP 状态、重试和阶段 |
| `strategy.jsonl` | 搜索/调度/共享/定位/停止证书决策 |
| `result.json` | 本局状态、清除频道、停止证书、时间分解和计数 |

对官方演练，`result.json` 中的 `official_total` 和 `clearance_ratio` 按设计为 `null`，因为官方 HTTP 接口不返回隐藏案例总数。不要把它们手工写进 `result.json`，应从模拟器结束界面抄录到单独的演练登记表。

### 5.2 每局验收条件

一局可记为“完成”需要同时满足：

1. `result.json.status == "complete"`；
2. `result.json.exit_confirmed == true`；
3. `result.json.failure == null`；
4. 模拟器界面显示本局为演练，且给出了源总数和清除数；
5. 清除数等于源总数，清除比例为 1.0；
6. `stopping_certificate.method` 为 `source_count_upper_bound`、`seven_station_channel_cover`，或代码确实启用时的 `continuous_disk_union`；
7. 没有超时、技术异常或未确认的传输动作。

若 `status=incomplete`，这局必须按失败/异常记录，保留全部原始日志；不要把它改成 `complete`，也不要用自建案例结果替代官方界面数据。

### 5.3 建议的演练登记表

每完成一局，立即记录：

| 字段 | 填写内容 |
|---|---|
| 演练编号 | `windows_recommended_001` 等 |
| 日期和开始时间 | 模拟器界面时间 |
| 案例编码 | 模拟器结束界面显示值 |
| 配置名 | 必须为 `round19_BOTH` |
| 配置 SHA-256 | `config.json` 的校验值 |
| 干扰源总数 | 模拟器演练结束界面 |
| 被清除个数 | 模拟器演练结束界面及 `cleared_channels` 交叉核对 |
| 清除比例 | `被清除个数 / 干扰源总数` |
| 定位清除总时间 | `result.json.metrics.virtual_time_s`，并与界面核对 |
| 平均定位清除时间 | `定位清除总时间 / 被清除个数` |
| 测量/清除/重试次数 | `metrics.counts` |
| 停止证书 | `stopping_certificate.method` |
| 模拟器原始日志文件名 | 导出后原名，不改名 |
| 异常说明 | 连接、超时、手工中止等 |

题面中的统计公式为：

```text
被清除干扰源个数的比例 = 被清除干扰源个数 / 干扰源总数
平均定位清除时间       = 定位清除总时间 / 被清除干扰源个数
```

定位清除总时间必须包含移动、切换频道、检测、光学精确定位和清除时间。客户端的 `metrics.components` 已分别记录这些分量；不要只统计光学或清除动作。

### 5.4 导出模拟器日志

演练结束后，使用模拟器界面提供的日志导出功能导出本局行为日志：

- 保留模拟器生成的原始文件名和扩展名；
- 不打开、解密、编辑或重命名日志；
- 将它与本局 `windows_recommended_###` 目录对应保存；
- 若界面显示上传队列或上传状态，确认日志已进入队列；
- 客户端的 `actions.jsonl`/`strategy.jsonl` 是调试和复核日志，不能替代模拟器要求的加密行为日志。

## 6. 常见问题处理

| 现象 | 处理 |
|---|---|
| 连接被拒绝/无响应 | 确认已结束倒计时且界面显示接口就绪；检查端口和 `--url`；不要在接口未开放时反复启动脚本 |
| HTTP 200 但 `accepted=false` | 优先检查队号、模式、请求体字段；保留输出，不把该动作当成已执行 |
| HTTP 400/404/415 | 通常是地址、路径、JSON、Content-Type 或字段格式问题；不要手工改发送内容绕过客户端校验 |
| `TransportUncertain` | 同一动作的重试已无法确认状态；保留日志，停止继续发送新动作，先观察模拟器是否已结束 |
| `status=incomplete` 且接近截止时间 | 记录 `failure` 和最后一个响应；不要事后补发 `/exit`；下一局使用新的输出目录 |
| 输出目录已存在 | 换新的目录名；不要删除旧日志来“重跑” |
| `config.json` 中没有 `mechanism=gated_tour_multi_parallax` | 立即停止，说明误用了旧入口。新入口不接受 `--config`，会固定读取 `question3/innovation/best_candidate.json` |
| 旧 `windows_rehearsal_*` 结果被误认为最终成绩 | 这些历史目录使用 `round1_AB`；只能作为旧版流程记录，最终方案必须重新运行并核对 `config.json` |
| 自建 HTTP 成功但官方失败 | 自建环境不含官方网络/登录/窗口状态；保留官方日志和界面信息，先排查队号、端口、进入时机和网络，不要直接宣称算法通过 |

## 7. 演练完成后的汇总建议

至少完成若干局覆盖不同随机案例后，再汇总以下指标：

- 总演练局数；
- 完整结束局数；
- 总清除比例及每局清除比例；
- 平均定位清除时间（建议同时给出均值、P95 和最大值）；

- 代表性成功日志和所有异常日志的文件名对应关系。

汇总时必须区分：

1. **自建模拟结果**：来自 `self_server.py`、`run_matrix.py` 或本机回环 HTTP；
2. **官方演练结果**：来自 `jammers-simulator.exe` 的演练界面、客户端日志和模拟器导出日志；
