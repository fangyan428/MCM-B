# 第二轮：终点区域前瞻、针对性消融与新案例审查

本轮承接用户“继续”，完成一次有界改进验证；现暂停人工审查，未冻结最终方案。所有结果均来自Ubuntu自建环境，Windows及官方演练均未执行，正式测试未授权、未启动，exe未运行，第四问未展开。

**推荐仍用原AB作为待审候选，不合入本轮前瞻。** H05在新布局中平均更慢且存在34.74%的单例回退。T的均值收益仅约0.14%，中位收益为零，最差回退28.48%，也不作为默认性能改进。保留全部代码、配置和负面证据，不追加参数搜索。

## 1. 承接第二问及三条方向

第一轮A改变优化目标：由局部定位直径转为移动、测向和后续光学覆盖的代价代理；B改变时间取舍：在搜索与已发现源定位之间安排次序；C利用合法先验：目标圆域、测向、接收与无信号、失败清除反馈用于安全覆盖剪枝。八种单项/兼容组合及定位精度—移动权衡仍见第一轮报告和第二问权衡稿，没有重写原成果。

本轮只针对B的调度机制改进，继续使用A同一个16点解析安全候选库、1.005°包络和光学覆盖。没有因路线得分更好而放宽第二点保证。第二问的有限库采样直径不是连续最坏界，(800,605)也不是通用最优；本轮的调度代理更不是全局时间最优定理。A允许较大定位区域换取较少移动的结论仍按第一轮数据陈述，本轮未重复检验A相对原始基线的增量。

## 2. 六种开发配置与机制

| 配置 | 唯一配置定义/相邻对照含义 |
|---|---|
| AB | 第一轮原AB，最近任务起点调度，作为对照 |
| T | AB加距离差≤10⁻⁷米时按固定ID处理平局；包括站点和源任务 |
| H0 | T改用完整任务代价与候选终点区域评分，下一任务项权重0 |
| H05 | H0加下一任务锚点移动项，权重0.5 |
| H1 | 同一项权重1 |
| P1 | H1的终点区域样本改为样本几何均值，作点估计消融 |

保留搜索最多被连续两次定位推迟的规则。站点扫描成本按尚未发现频道计数；定位评分含当前位置到第二点、第二检测、代理光学成本、第二点到候选源终点的移动。前瞻项加上终点到剩余站点或其他源第二点锚点的最近距离，其他源第二点按本次决策时的当前位置固定估计。

终点区域用31个半径×3个角偏差，共93个固定样本，结合目标圆域和此前无信号反馈过滤。这些样本只用于评分；若采样全部被过滤则回退原样本，不宣称候选域为空。区域评分取样本中的最大移动代价；点消融取几何均值，均不代表概率分布。真实清除终点距源可有20米误差，第二次测向及实际光学路径也未完全计入预测，因此该评分是启发式。H0与T同时改变了任务估价与终点建模，不能把二者差异全归因于某一个因素；H05对H0隔离了下一锚点项，H1对P1隔离了区域样本对点估计的作用。

数值平局最小复现：原点到六环站理论上均1500米，但当前浮点中站3为1499.9999999999998，原规则因此选3，T按ID选1。该差异不破坏覆盖证明，却能改变整条路线。修正数值规则不等于证明更省时，且尚未实测Windows跨平台一致性。

## 3. 实验隔离与预算

开发仍为16种布局（12种布局×4种误差场，加4种针对性布局），每配置52局。六种配置各一套固定参数，仅比较预先声明的两个前瞻权重；H0、P1作消融。开发主环境和舍入压力各312局。

按预先声明的“零失败优先，其次主开发均值，再P95”在H05/H1中选择H05，即使二者都不如AB，也保留这个负面选择进入验证。先写入`results/round2_lock.json`的代码SHA256及精确配置，再运行独立生成器，生成此前未运行的种子10000—10049。锁不是最终方案冻结，只是本次实验的防调参边界。

新验证为50种布局×4种固定误差场，共200个配置案例；AB、T、H0、H05各运行一次，主环境800局，舍入压力另800局。四方案使用完全相同的场景与误差函数；同点同频道误差固定，不重新抽样。两个批次只是两种舍入解释，不是100种独立布局，更不是1600个独立布局。验证期间及结束后未修改锁内代码或调参。主批总误差≤1°；压力批允许先加偏差后两位小数舍入形成≤1.005°，单独标识。

失败、超时、未认证运行全部保留，排名目标对其计至少360000秒罚值；本轮实际没有这类运行，所以带罚均值恰等于全部运行原始均值。清除尝试失败是合法反馈，不等于整局失败。以下P95用全部案例线性分位数，尾10%为最慢ceil(0.1n)局均值，不删除失败。

## 6. 最差案例与对抗式复核

1. H05相对AB最差新案例为`holdout_10031_spatial_hash`：4515.98→6084.71秒，回退34.74%。移动从3778.98升到5398.71秒，尽管测向/光学等减少51秒仍无法补偿。AB首站后立即清除频道13、18，H05先连续扫站0、3、4、5。原始路线与决定时的全部代理分数保存在strategy.jsonl。
2. T相对AB最差新案例为`holdout_10035_spatial_hash`：5203.83→6685.64秒，回退28.48%。首次等距定位任务由频道5变成1，后续路径改变；移动增加1535.81秒。该例说明微小局部平局规则能改变后续路线，固定ID不是性能保证。
3. AB仍有未解决尾部：主新集最大6815.33秒（`holdout_10005_positive`），舍入压力最大6961.09秒（`holdout_10005_negative`）；第一轮边界最小R布局主环境6835.23秒，聚集布局仍2431秒，较原固定搜索基线2239秒慢8.58%。AB单局最多41次光学失败后才全部成功，不能把这些尝试删掉或称为零失败清除。

## 7. 结论等级、后续一项机制与审查

**已证明（题设及计算正确条件下）**：第二点解析充分条件、七站连续覆盖、有限光学覆盖及逐频道停止证书。本轮只改变访问次序和评分，不借助评分样本删源，不降低这些保证；预算或协议异常仍明确incomplete。浮点代码不是形式化认证。

**实验支持**：原AB在第一轮开发的收益；本轮锁参新布局全部完整清除；H05、H0性能未达到预先提出的中位改善≥5%且单例最差回退≤10%目标，T亦不达标。这些阈值是项目审查标准，不是赛题规则。新集只有AB与T/H0/H05，不能据此宣称AB在新集比第一轮所有八种配置都好。

**自行选择/待验证**：候选点库、成本代理、终点采样和前瞻权重；通用最优、任意误差场表现、Windows和官方接口兼容均未获证明。验收集已经使用，未来若据此改策略必须另外预留新案例，不再把本集称为未见集。

若审查后仍要再研究，仅建议一项机制：**在同一小任务集合上比较两种执行顺序的增量移动**。现缺陷是扫描一个短任务与清完一个源的完整成本直接竞争；可让两条方案都完成同一个“扫描站＋已发现源”任务集合，仅比较先后顺序的移动差，避免把必做的清除成本只罚给其中一项。预计收益是恢复可比的规划范围，代价是额外局部路径估计；仍存在未知新源和定位终点不准的问题。对照原AB和本轮H05，保持接收/覆盖/停止机制不变；若出现漏源或假完成立即放弃，若新的预留集仍不达上述收益/回退目标则不合入。**本项未实现、未运行，不在本轮继续调参。**

当前暂停在“改进验证完成”。建议人工审查决定：是否接受保留原AB为候选、放弃本次前瞻并不合入T；下一步是单独评估上述一项机制，还是进入Windows官方演练准备。最终方案冻结和任何正式测试仍需另行明确确认。
