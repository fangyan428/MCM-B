# 问题4最新方案演练测试使用说明

本文说明当前仓库中第四问方案的自建 HTTP 回归和 Windows 官方模拟器演练流程。所有命令均在项目根目录 `E:\国赛数模\MCM-B` 的 PowerShell 中执行。

## 1. 先确认“最新方案”对应哪个入口

当前可用于官方第四问演练的入口是：

```text
question4.run_http
```

默认读取：

```text
question4/configs/recommended.json
```

该配置是当前冻结的 25 站推荐方案，包含：

- 25 站双环覆盖；
- 定位区域面积重心驱动的开放路径调度；
- 低信息量检测删减；
- 已知 16 个源时的上界停止；
- 正向测向交会定位和光学覆盖兜底。

`question4/innovation/best_candidate.json` 中的 `ADAPT_GATED` 只是追加自建实验候选，内容是 `mechanism/sharing` 描述，不是 `question4.strategy` 接受的扁平配置，不能直接通过 `--config` 用于官方演练。仓库报告明确保留 `configs/recommended.json` 作为官方演练推荐入口；不要把创新候选的自建成绩当作官方成绩。

## 2. 环境准备

在项目根目录执行：

```powershell
Set-Location E:\国赛数模\MCM-B
python --version
python -m pip install -r question4/requirements.txt
```

依赖为 NumPy 2.4.4 和 SciPy 1.17.1。建议使用已验证的独立 Python 环境；演练过程中不要临时升级依赖或替换源码。

## 3. 先做自建 HTTP 回归

自建服务只验证“策略—HTTP 客户端—日志—停止证书”链路，不启动官方模拟器，也不模拟登录、服务器时间、窗口倒计时或加密官方日志。

打开两个 PowerShell 窗口。

窗口 A 启动第四问自建服务：

```powershell
Set-Location E:\国赛数模\MCM-B
python -m question4.self_server --port 2028 --seed 0 --family outward
```

看到类似以下输出后保持窗口 A 运行：

```text
SELF Q4 http://127.0.0.1:2028 robot_id=SELF
```

窗口 B 运行推荐方案：

```powershell
Set-Location E:\国赛数模\MCM-B
python -m question4.run_http `
  --mode self-http `
  --url http://127.0.0.1:2028 `
  --output question4/results/self_q4_recommended_20260912_01
```

输出目录必须事先不存在；每次换用新的目录名，例如 `_02`、`_03`，不要覆盖旧日志。成功时应看到 `status` 为 `complete`，并且 `result.json` 中 `mode` 为 `self-http`、`official_total` 和 `official_clearance_ratio` 为 `null`。输出目录应包含：

| 文件 | 作用 |
|---|---|
| `config.json` | 本次实际使用的推荐配置副本 |
| `actions.jsonl` | 每次 HTTP 请求、响应、状态码、重试和阶段 |
| `strategy.jsonl` | 搜索、定位、调度、光学兜底和停止决策 |
| `result.json` | 状态、清除频道、时间分解、停止证书和计数 |

自建回归通过后按 `Ctrl+C` 停止窗口 A。若要换 seed 或案例族，重新启动服务并使用新的输出目录。

也可以执行完整回归测试：

```powershell
python -m unittest question4.tests.test_cover_http question4.tests.test_contract question4.tests.test_faults -v
```

这组测试覆盖方向源背面、近场清除、误差极值、连续覆盖证书、幂等重试、状态不确定和真实 loopback HTTP 往返。通过它只代表本机代码回归通过，不代表官方模拟器已通过。

## 4. Windows 官方第四问演练

### 4.1 在模拟器界面操作

1. 启动官方模拟器程序并完成登录、联网和服务器时间校验。
2. 手工选择“问题4演练测试”（rehearsal/practice）。不得选择正式测试。
3. 等待案例准备完成、倒计时结束，并确认界面显示机器狗 HTTP 接口已就绪。
4. 保持模拟器窗口和本 PowerShell 在同一台电脑上运行。

官方接口默认地址为：

```text
http://127.0.0.1:2026
```

如果模拟器界面显示了其他端口，必须在命令中显式加入 `--url http://127.0.0.1:实际端口`。不要让自建服务占用 2026 端口。

### 4.2 启动客户端

接口就绪后，在新的 PowerShell 窗口执行：

```powershell
Set-Location E:\国赛数模\MCM-B
python -m question4.run_http `
  --mode official-rehearsal `
  --confirm-rehearsal-ui `
  --robot-id YOUR_TEAM_ID `
  --output question4/results/windows_q4_rehearsal_001
```

替换以下内容：

- `YOUR_TEAM_ID`：替换为当前模拟器登录的真实队号，必须与登录账号逐字一致，不能使用 `SELF`；
- `windows_q4_rehearsal_001`：必须是尚不存在的新目录；下一局使用 `002`、`003` 等；
- 非默认端口：增加 `--url http://127.0.0.1:端口`；
- 非默认配置：只有在确认该配置与 `question4.strategy.DEFAULT` 字段兼容时才使用 `--config`。官方演练建议不传该参数，让程序读取 `configs/recommended.json`。

`--confirm-rehearsal-ui` 只是操作者确认当前界面已选择第四问演练；HTTP 接口本身无法识别演练/正式模式。程序不会启动模拟器、点击按钮、选择模式或读取隐藏真值。

## 5. 程序实际执行和完整性规则

客户端按顺序调用 `/enter`、`/measure`、`/clear`、`/exit`。请求串行发送；新动作使用新 `request_id`，仅在传输异常时用相同 ID 重试。只有 HTTP 状态正常且 JSON 中 `accepted=true` 才推进本地虚拟时钟。

第四问与第三问不同：定向源背面或距离不足时的 `no_signal` 不能证明附近没有源。策略只把 `direction` 返回的方位角用于收缩保守可行区域，并始终保留光学兜底。`/clear` 不切换测向频道；只有 `/measure` 会产生切频成本。

时间和接口注意事项：

- 必须先 `/enter`，进入成功后才能测量或清除，最后调用 `/exit`；
- `/enter` 返回的现实剩余时间决定本局截止，不能假定总是 1200 秒；
- 客户端默认在截止前保留 5 秒安全余量；
- 坐标必须为有限数，且每个分量绝对值不超过 2,000,000；频道必须为 1—20 的整数；
- `accepted=false`、业务拒绝、时间核算不一致或重试耗尽时，状态不得当作完成；
- 若上一次动作响应是否执行无法确认，不要换新 ID 盲目重发，也不要事后伪造 `/exit`。

## 6. 一局完成后的验收和登记

客户端完成的最低条件是：

1. `result.json.status` 为 `complete`；
2. `result.json.failure` 不存在或为空；
3. `result.json.cleared` 为实际被成功清除的频道列表；
4. `result.json.stop_certificate` 存在且与配置、动作日志一致；
5. 模拟器界面确认本局确实是“问题4演练测试”；
6. 以模拟器界面给出的源总数和清除数判断清除比例，不能用客户端的 `official_total=null` 代替。

建议每局立即登记：

| 字段 | 来源 |
|---|---|
| 演练编号、日期、开始时间 | 模拟器/人工登记 |
| 案例编码 | 模拟器结束界面 |
| 方案配置 | `config.json`，应为 `configs/recommended.json` 内容 |
| 源总数、清除数、清除比例 | 模拟器结束界面 |
| 总虚拟时间 | `result.json.metrics.virtual_time_s` |
| 移动、切频、检测、光学、激光时间 | `result.json.metrics.components` |
| 测量/清除/成功/失败/重试次数 | `result.json.metrics.counts` |
| 停止证书 | `result.json.stop_certificate.kind` |
| 异常和最后响应 | `result.json.failure`、`actions.jsonl` |

题面统计公式为：

```text
清除比例 = 被清除干扰源个数 / 干扰源总数
平均定位清除时间 = 定位清除总虚拟时间 / 被清除干扰源个数
```

总虚拟时间应包含移动、切频、无线电检测、光学尝试和成功清除成本；不要只记录激光时间或实际壁钟时间。

## 7. 官方日志保存

演练结束后使用模拟器界面的官方日志导出功能保存本局日志：

- 保留官方生成的原始文件名和扩展名；
- 不编辑、解密、重命名或删除官方加密日志；
- 将官方日志与对应的 `windows_q4_rehearsal_###` 客户端目录配对保存；
- 客户端的 `actions.jsonl` 和 `strategy.jsonl` 只能用于调试、复核，不能替代模拟器要求的官方加密行为日志。

## 8. 常见异常处理

| 现象 | 处理 |
|---|---|
| 连接被拒绝 | 确认倒计时已结束且界面显示接口就绪；核对 2026 端口和 `--url` |
| `accepted=false` | 检查队号、接口地址、当前模式和进入时机；保留该目录，不把动作算作成功 |
| HTTP 400/404/415 | 检查路径、Content-Type、端口和是否误接入自建服务；不要手工绕过客户端校验 |
| `TransportUncertain` | 停止继续发动作，保留最后请求/响应日志，先观察模拟器状态 |
| `status=incomplete` | 按异常局登记，保留日志；不要改写为 `complete` 或在同一局盲目重跑 |
| 输出目录已存在 | 换新目录；不要删除旧证据来重跑 |
| 队号为 `SELF` 或未传确认参数 | 官方模式会在 `/enter` 前拒绝，改用真实队号并确认界面 |
| 自建成功、官方失败 | 分开排查登录、队号、端口、时间窗口和网络；自建结果不能替代官方结果 |

## 9. 自建、官方演练和正式测试的边界

必须分别保存三类记录：

1. 自建 HTTP：`question4.self_server` 产生，只证明本机协议和策略链路；
2. 官方演练：官方模拟器界面、客户端目录和官方导出日志共同证明；
3. 正式测试：需由操作者在模拟器中另行确认并按竞赛规则执行。

当前 `question4.run_http` 没有正式测试模式，也不会自动启动或操作正式测试。不要把自建结果、创新候选结果、旧版本结果或演练结果改名后填入正式测试表。官方演练和正式测试的实际总数、案例编码、清除比例及官方日志，均须以模拟器界面和导出文件为准。
