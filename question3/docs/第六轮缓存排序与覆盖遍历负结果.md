# 第三问第六轮：两个局部路径改进未通过采纳门槛

**维持第五轮推荐COMPACT_BATCH。本轮新增I、V和IV均保持关闭，不替换已验证运行包。** 优化目标仍是整局虚拟时间，完整清除和可靠停止先于时间比较；本轮没有启动官方exe、官方演练或正式测试。持续优化目标尚未完成。

## 机制与边界

I：`cache_routing=station_insertion`。原调度已经选择缓存清除任务时，改为按“当前位置→该源固定光学覆盖路径→当前最近未访搜索站”的完整遍历费用，减去直接到站移动费来排序。只用完成两次测角后的覆盖点，无未知源终点采样。原调度选择搜索、未缓存定位、强制搜索或已经访完七站时均保持原决策；C的动态覆盖路径和O另行排序与该模块不兼容，配置在enter前拒绝。

对固定路径p₁…pₙ、当前位置x、评分锚点s，费用为

`[|x−p₁| + Σ|pᵢ−pᵢ₊₁| + |pₙ−s| − |x−s|]/5 + 3n + 2`。

三角不等式说明它上界覆盖每一种成功清除前缀再到同一个s的费用。但下一站实际仍由原调度滚动选择，比较不同源还改变任务集合和剩余路线，所以**不是整局时间上界或最优排序证明**。

V：`optical_order=nearer_end`。同一光学蛇形覆盖点集允许正序/倒序，从离当前机器人较近的端点开始。缓存任务的调度入口与实际执行使用相同方向；方向在执行前依据当前位置确定。所有覆盖点保持不变，C动态排点与V不兼容。

正反遍历的内部路径长度相同，较近入口保证完整遍历移动距离不增加；**这不保证实际提前命中的时间不增加**，也不包含离开最终清除点去下一任务的费用。近场、第二点几何保证、固定同点误差、逐频道七站停止规则均不改变。两项机制都不读取真值或误差场类型。

配置默认值维持原行为。I和V可以组合；IV计分时使用V定向后的缓存路径，避免规划入口与执行入口不一致。第一问、第二问代码、HTTP接口和自建误差环境未改。

## 预先约定与实验范围

先写`round6_protocol.json`实现I，52既有开发配置×2方案×2舍入模型=208局。I均值变差后记录负结果，再写`round6_optical_protocol.json`，加入独立机制V与IV，按同一52配置运行四方案、两种舍入模型，共416局。没有扫描权重、概率先验或数值参数。

采纳规则在实验前写明：两种舍入模型中均需全局完整清除、审计通过、均值降低且P95不增加。没有在看到结果后放宽门槛。三个候选均未通过，因此**未生成种子70000—70049或80000—80019的新验证场景，本轮独立新验证为0**。

另外复用第五轮四个不利案例做32局诊断：普通最坏退化、普通绝对最慢、外缘最坏退化、近大环站聚集反例。它们现在属于已知开发案例，不再是本轮独立验证。通用运行器对外部fixture的`unseen_validation_cases_run`字段按加载数量计数，必须结合`SELF_ROUND6_REUSED_ADVERSE_DEVELOPMENT_NOT_UNSEEN`阶段标签解释，不能用这个字段宣称新增验证。

总计656局自建实验，全部完整清除、停止审计通过；失败/超时/假完成均0，审计77162条动作。每批全部保留，均值和尾部没有排除失败；失败惩罚至少360000秒。相同场景使用相同确定性误差函数，同点同频道误差固定。两种舍入模型及多个场景复用同一布局，不是独立样本数量的倍增。

原绕路案例中I没有改变结果，不能把实现了排序等同于解决了绕路。主开发批I只改变16个缓存选择，压力批20个；决策适用范围较窄，而且单个缓存任务的到站上界不能代表完整待办路线。

V在主开发批反转325次，累计减少约4194米的“进入该条原覆盖路径”的局部距离，但这是**同一时刻两种方向的比较**，不是相对REF整局节省的实际距离。最坏V案例`dev_6_positive`从5086.52增至5202.47秒：移动多58.94秒，光学多57秒（多19次失败尝试），检测/切频/激光不变。压力模型类似：移动多56.16秒、光学多54秒。因此近入口有时把真实命中点排得更晚，局部移动上界下降不足以证明实际命中更快。

IV比V单项均值更差约10.09秒（主批）和4.73秒（压力），没有支持叠加I的证据。不把普通方向参数或局部代理包装成普遍创新，也不以少数原反例改善掩盖新反例。

## 对抗检查、结论和继续方向

79项第三问测试通过，其中新增9项检查完整遍历上界、同一覆盖点集、规划/执行入口一致、数值平局保留、缓存/强制搜索边界、迟发现源、覆盖耗尽仍incomplete、配置不兼容在enter前拒绝。完整测试集包含已有本机HTTP测试；本轮新增I/V流程是在自建内存接口验证，不能声称已用官方HTTP检验I/V。

默认关闭I/V时，104局REF的费用分解、清除集合、状态、审计结果与第五轮逐局完全一致。诊断锁及六批矩阵完整性再次检查通过。当前推荐运行包仍用`releases/q3_omni_round5.zip`，`recommended_omni.json`没有改动。仓库加入了新实验模块，因此复现第五轮旧代码锁需使用第五轮运行包/代码快照，不能拿当前新增源码冒充第五轮锁内代码。

本轮得到两个有用反证：仅优化单个缓存任务到站费用不足以改善全局调度；从近端遍历也可能推迟实际命中。后续优先复核已有的**候选区可被单个20米圆覆盖时直接清除（D）**在小环、批量共享的新配置下的作用：它用完整候选区几何证书减少清除步骤，避免单纯猜测清除方向。D过去在另一配置中收益小且有反例，本轮尚未重测，不能直接开启。持续优化目标保持进行中。
