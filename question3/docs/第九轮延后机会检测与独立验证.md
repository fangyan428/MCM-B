# 第三问第九轮：先选任务，再决定是否原地检测

推荐研发方案改为**ZL：第七轮K + 在任务选定后尝试合法原地第二检测**。新布局普通主批均值降低0.769%，外缘主批降低0.642%；P95均下降。新普通案例仍有5.91%的单例退化，旧外缘反例仍有6.29%退化。本轮没有证明逐例更快，未冻结最终比赛方案，持续优化继续进行。

## 机制与证据边界

上一轮在构造全部待办任务时就把合法原地检测点设成距离0，可能让本来排在后面的源提前执行。本轮新增`opportunity_timing=after_schedule`：

1. 搜索/定位调度仍使用原A目录点、已定位缓存的原任务入口，按原B选择任务；强制搜索和K数量证书不改。
2. 若选中未完成第二次检测的源，再检查当前位置是否满足第二问完整解析候选条件。
3. JL只有原费用代理更低才原地检测；ZL只要解析条件成立就原地检测，否则走原目录点。缓存任务直接清除，不再测量。

每次机会点均保证接收、排除退化近场、满足20°最小交角和1.005°误差包络；之后仍做完整光学覆盖或合法停止证明。原地检测仍有5秒检测费及必要切频费，同点误差固定，不重复测量平均降噪。策略不读隐藏位置、数量或误差场类型。

L只保证**同一当前状态下，调度输入仍是原目录，当前任务先确定再改点**。实际第二点会改变观测、共享缓存和清除终点，后续状态和任务顺序仍可能变化，不能声称整个路线不变或全局更优。费用代理和采样直径仍是启发式，Q1/Q2代码、HTTP接口与自建物理环境均未修改。

## 对照设计及候选范围说明

五个方案为REF（第七轮K）、J、Z、JL、ZL。J/Z保持第八轮定义；后缀L仅改变机会点选择时机。相同52开发配置、固定误差场、两种舍入模型，共520局；复用8个旧反例做80局开发诊断，均不算新独立验证。

初始`round9_protocol.json`对“合格方案”的表述未区分旧控制与新候选。新验证生成前，另写`round9_candidate_scope.json`明确只有新增JL/ZL可被本轮选中，REF/J/Z用于消融；Z已经在第八轮独立验证失败，不凭相同开发结果重新推荐。原协议与修订均保留。这是候选范围说明，不是看到新验证结果后改变阈值。

JL/ZL开发均值和P95均不高于REF，按新增候选中主批均值最低选ZL。写`round9_lock.json`后才生成普通130000—130049、外缘140000—140019，共50+20种独立新布局，各4固定误差场、两种舍入模型、五种方案，共2800局验证。选中ZL后未调参，四个新批次均通过事先的完整清除、审计、均值降低和P95不增加门槛。

本轮合计**3400局自建实验，全部完整清除，失败/超时/假完成0，407990条动作审计通过**。所有局内失败清除和费用保留；不存在删失败后求均值。新布局数是70，不是2800。97项测试通过；312局原REF/J/Z与上一轮费用分解、清除状态和审计结果完全一致。JL/ZL另各经一次真实Ubuntu本机HTTP命令运行，均实际发生原地检测并完整清除。官方exe、官方演练、正式测试、Windows运行均未实际执行。

## 结论、继续方向与复现

在当前自建证据与预设目标下推荐ZL，保留第七轮K作为基线，D/I/V仍关闭。已证明的是几何合法性、同点固定误差约束、单次任务先确定的时序、覆盖/计数停止可靠性；均值/P95改进只有自建实验支持。没有证明每局更快，官方一致性和Windows仍待实际运行。

新增4项测试检查调度器看到的未缓存任务均为原目录点、延后事件频道与已选任务一致、缓存不重复测量、迟发现源、调度后截止时间耗尽必须incomplete，以及无机会功能时的兼容性。全部97项通过。状态、配置和源码锁再次核对，验证期间没有修改策略。

下一项应隔离**原地第二点改变共享缓存集合**的影响：仍保持选定任务和原地几何条件，仅对原地测量后的额外共享批次做开/关消融，记录缓存集合和整局费用。该机制尚未实现，不能预设关闭共享会更好；原有共享S在普通路径上的收益应保留，不盲目撤销。需用旧外缘反例诊断，再锁定新案例验证。
